# 架构概览

## 进程边界

- `src/main`：Electron 生命周期、窗口、托盘、原生监听、通知、文件、数据库入口和 IPC。
- `src/preload`：通过 `contextBridge` 暴露 `DesktopApi`，不暴露 `ipcRenderer`。
- `src/renderer`：桌宠、控制中心和工具窗口，不直接访问 Node 或 Electron。
- `src/shared`：主进程和渲染进程均可使用的纯类型、常量与纯函数。

渲染进程启用沙箱和上下文隔离，关闭 Node 集成。IPC 写操作校验发送窗口、主框架、参数数量、
类型、范围和业务状态。

## 业务边界

- `src/features`：成长、外观、签到、成就和背包经济。
- `src/tools`：番茄钟、便签、久坐、总结、待办、喝水、倒计时和纪念日。
- `src/services`：统计存储、输入监听、偏好和奖励等跨功能服务。
- `src/data/catalogs`：角色、装扮、默认锚点、地毯、解锁、经济和工具目录。

服务通过公开类型或数据库事务协作，不依赖其他模块的 UI 内部状态。

## 数据库

`StatisticsStore` 使用 Node 内置 SQLite，当前 `user_version = 17`。

打开旧数据库时，迁移开始前先通过 SQLite `VACUUM INTO` 生成一致性备份
`statistics.pre-v17.sqlite`；已有备份不会被后续启动覆盖。

- v1–v14：统计、成长、钱包、基础外观和工具基础数据。
- v15：五槽位外观、碎片、签到、成就和扩展工具。
- v16：掉落进度、掉落记录、发现记录、心愿、经济流水及桌宠显示偏好。
- v17：`item_adjustments`，按 `(character_id, item_id)` 保存偏移和缩放。

输入统计、经验、掉落、库存和等级奖励在同一事务结算。外观微调通过 `AppearanceService`
校验，只允许修改当前伙伴正在佩戴的有效装扮；默认值会删除覆盖记录。

完整重置清除所有用户表并恢复新账号状态；“清除统计”只删除每日统计，不清除成长、掉落
进度、背包或外观微调。

## 桌宠渲染

1. `appearance.ts` 提供角色和装扮目录。
2. `anchors.ts` 计算角色槽位默认锚点和单件素材校正。
3. 用户微调在默认锚点后应用，使用角色 256×256 画布单位。
4. `App.tsx` 和 `PetPreview.tsx` 调用同一个 `resolvedAnchor`，确保桌面与预览一致。
5. 主进程按用户缩放调整 BrowserWindow 与 WebContents；命中区域同步缩放。

## 输入与状态

`uiohook-napi` 只在主进程加载。有效按下会立即向桌宠发送仅含“键盘或鼠标”类别的动作脉冲，
连续同类脉冲交替动画名称以重新播放；统计仍按约 5 秒聚合并落库。渲染进程不接收原生事件
对象，锁屏、休眠或暂停期间不计数。

桌宠状态机统一处理拖动、升级、掉落、键鼠反馈、专注、休息、睡眠和边缘状态，避免多个
组件同时决定动画。

主进程拖动使用 `pet-drag.ts` 的纯逻辑：贴边状态先吸收 6–10px 向内位移，越过后释放并
使用完整鼠标位移；同一次拖动松手时排除刚脱离的边缘，避免立即吸回。贴边动画的命中框
额外扩展 8 个画布像素，确保动画移出的可见部分仍能开始拖动。

## 资源与打包

- 角色、装扮和界面资源位于 `public/assets`。
- 来源与哈希记录在 `public/assets/licenses/sources.json`。
- `npm run validate:assets` 校验引用、尺寸、透明通道和登记。
- Forge 打包钩子复制并解包原生监听模块；`npm run check:package` 校验分发目录。

发布前还必须在项目外运行 `--input-hook-smoke-test`，避免仓库依赖造成误报。
